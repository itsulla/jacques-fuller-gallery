# Impeccable Critique — Jacques Fuller Living Sculpture Archive

## Design-specificity verdict

**Strongly authored, but not yet fully specific to Jacques Fuller.**

The site has a coherent monograph language: oversized literary serif typography, mineral/paper fields, fine catalogue rules, an oxide-dark archive chapter, and asymmetrical selected-work layouts. It already feels more intentional than a generic portfolio. However, its current visual grammar—large serif, Swiss grid, small uppercase labels, cobalt actions, generous whitespace—could still be transferred to a ceramicist or architecture monograph with limited changes. Fuller's own material vocabulary (brass, mild steel, found machinery, patina, welds, mechanical creatures, Bloemfontein) appears mainly in the photographs and copy rather than shaping the interface.

## What is working

1. **A credible visual world.** Mineral grey, oxide black, restrained cobalt, fine rules, catalogue numbers, and serif display type establish seriousness without generic black-and-gold luxury styling.
2. **Sound content architecture in principle.** Hero → selected works → living archive → artist → complete archive → artwork viewer separates curatorial emphasis from archival completeness.
3. **Strong object-first moments.** Ship of Fools and Blind Butcher receive enough scale and space to feel like sculptures rather than thumbnails.
4. **Good interaction foundations.** Fresh desktop/mobile browser tests found no horizontal overflow, console errors, failed requests, or broken images. All six featured records opened. Arrow navigation, Escape, focus restoration, scroll lock, reduced-motion handling, and meaningful alt text work.

## Priority issues

### [P1] Make the six selected sculptures load and appear as the primary product

**Why:** The deterministic browser pass found no broken images; the placeholders are lazy-loading states, not failures. But visually they still dominate large wells during a fresh traversal. In a sculpture archive, an empty image stage temporarily removes the core content.

**Fix:** Prioritize/preload all six selected lead images; keep the 24 archive thumbnails lazy; use the existing thumbnail variants rather than full views in the grid; shorten the placeholder transition; preload the next selected work near the viewport; add retry/open-original only for true failures.

**Impeccable:** `$impeccable optimize`, then `$impeccable polish`.

### [P1] Stop narrating the prototype everywhere

**Why:** “Prototype selection,” “working archive,” “intentionally temporary,” and repeated “to be confirmed” language make the public page sound like an internal staging document. Honesty is correct; repetition reduces authority.

**Fix:** Put one concise archive-status note near the introduction. Model metadata as Confirmed / Awaiting family review / Not recorded. Hide absent fields from selected-work summaries and show status once inside the full record. Replace product-roadmap copy with actual content as it arrives.

**Impeccable:** `$impeccable clarify`.

### [P1] Separate exhibition mode from catalogue mode

**Why:** The visitor currently traverses six full editorial records, a future-facing archive chapter, the artist biography, and then 24 inventory cards. A curator seeking one work must scroll a very long surface.

**Fix:** Add a clear “Browse all 24 works” action in the first viewport; create a distinct Archive route or strong in-page mode switch; add title/archive-number search; add material filters only after metadata is complete; keep persistent Selected / Archive / Artist context.

**Impeccable:** `$impeccable shape`, then `$impeccable layout`.

### [P1] Fully isolate and announce the artwork viewer

**Why:** The viewer focuses Close, traps focus, locks scrolling, supports Escape, and restores the trigger. But the background page remains exposed in the accessibility tree, and photo changes are not explicitly announced.

**Fix:** Set the background application inert while the dialog is open; provide a stable accessible name/description; announce “Photograph X of Y” through a polite live region; validate with screen-reader and keyboard-only tests.

**Impeccable:** `$impeccable audit`, then `$impeccable harden`.

### [P2] Let the viewer become an image-study environment

**Why:** The dark viewer has atmosphere, but metadata competes with the active image and the opening stage does not feel immersive enough.

**Fix:** Give the sculpture roughly 70–75% of the desktop stage; place thumbnails in a persistent adjacent/horizontal rail; make the current image count more legible; add a zoom/full-resolution affordance when the source supports it; make visual Previous/Next labels unambiguous.

**Impeccable:** `$impeccable layout`, then `$impeccable delight`.

### [P2] Make the interface materially Jacques Fuller, not just editorial-gallery

**Why:** The cobalt buttons are accessible, but visually imported. The system does not yet draw enough from brass, oxidation, weld seams, mechanical indexing, or the local workshop context.

**Fix:** Replace ubiquitous cobalt blocks with a restrained patinated-copper/verdigris accent; reserve strong fill for one primary action; use quieter text/rule actions elsewhere; introduce one or two structural motifs inspired by workshop index marks or joined metal—not decorative steampunk texture.

**Impeccable:** `$impeccable colorize`, then `$impeccable bolder`.

### [P2] Tighten small-screen controls and rhythm

**Why:** Playwright found the mobile Artist link at 42×44px—two pixels below the width target. Six 70svh selected-work images and a single-column archive create substantial thumb-travel.

**Fix:** Normalize all persistent controls to at least 44×44px; use a compact sticky section switcher; shorten selected-work stages on mobile; keep the archive in a denser two-column treatment where image legibility permits.

**Impeccable:** `$impeccable adapt`.

## Cognitive-load assessment

Five of eight checks fail or partially fail: the page combines exhibition, future archive, biography, and inventory in one linear surface; the six selected records plus 24-card archive are insufficiently chunked; duplicate image/card actions add choice; the archive is a decision wall without search; and the visitor must remember their section while scrolling. Grouping within individual records is strong, but progressive disclosure is weak.

## Persona red flags

### First-time collector or curator
- No confident enquiry, provenance, availability, commission-history, or contact action.
- Duplicate titles such as Safari need disambiguation.
- Repeated unresolved metadata reduces research credibility.
- The long monograph is inefficient for known-item lookup.

### Accessibility-dependent visitor
- Background content remains semantically reachable while the dialog is open.
- Photo changes lack a live announcement.
- Small uppercase metadata and long keyboard traversal add effort.
- Failure states lack retry or alternate access.

### Distracted mobile visitor
- The page demands a long thumb-driven sequence before the complete archive.
- There is no persistent, thumb-friendly archive jump.
- Horizontal viewer thumbnails work but are not visually obvious as a control.
- One navigation target is slightly below the 44px width guideline.

## Minor observations

- Standardize “views” versus “photographs.”
- Remove the duplicate “Open catalogue record” action when the image already opens it.
- Avoid truncating Mallemeule Merry-Go-Round in the archive grid.
- Confirm “Beaurocrat” and preserve album-source truth with a note if intentionally spelled that way.
- Collapse the large Voice / Studio / Record roadmap until at least one real story, workshop fragment, or document exists.
- The hero-name blocker found during the independent browser pass was corrected before production verification: the live page now renders Jacques Fuller and JF-001–JF-024, with no René or JRF strings.
